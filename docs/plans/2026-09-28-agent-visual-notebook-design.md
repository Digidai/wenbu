# Agent 图解札记设计

目标：减少独立 Agent 工作台中同时出现的连续长段落，让入口、过程、结果与依据各有清晰的视觉表达。保留现有四种工具、会话、导出、DeepSeek 与 Cloudflare 架构。

## 选择

采用「图解札记」：细线器物图标、低饱和纸色、短对照与有序步骤。相比只添加插画，这能改变实际阅读方式；相比自动把任意正文变成统计图，它有明确的结构和出处，不会暗示不存在的量化结果。

- 入口：六枚原创 SVG 图标用于四种工具、资料与札记。卡片只显示简短用途，点击仍填入完整问题。空态的叠纸插画说明结果区域的作用。
- 过程：根据真实工具调用聚合成查阅、推演、成稿与补充的过程条；次数是实际调用数。点击展开原始记录。失败或停止有始终可见的数量提示，记录默认展开，不抹去早先失败。
- 回答：Markdown 原文保留，一级要点形成留白清晰的条目。
- 报告：实数统计展示章节、已知引用来源和图解数量；图解前置，完整摘要在其后标明概览与边界。章节可逐一展开或展开全文。模型被要求把重大限制也写入摘要。
- 图解：为 write_report 增加可选 visual（comparison / steps）。每项包括简短标题、说明和独立 sourceIds；点击项目切换依据。至多四项，不接受任意图表代码、HTML、颜色或分数。
- 资料：以统一图标、类型、来源域名呈现，完整已读摘录按需展开。

## 数据和兼容

旧报告不要求 visual，不推测或补造历史图解。新增图解进入会话保存、续聊上下文与 Markdown 导出。图解独有的来源同样经过引用校验，外部引用在报告修订前重新读取；用户提供的旧报告仍是草稿而非证据。所有报告文本合计仍受 1,800 字符约束。公开请求 schema、OpenAPI 和协议说明同步更新。

## 动效和可访问性

仅增加短的纸张入场、图标悬停反馈、图解到达和章节展开。没有新增延时、伪进度或随机结果。遵循既有暂停动效和系统减少动效设置。SVG 为装饰；操作使用按钮与原生 details/summary，保留键盘行为与文字名称。图解同时保留文本和来源，不依赖颜色理解。

## 验收

- 单元与集成：旧协议、图解边界、仅图解引用的来源校验和重读、导出与续聊。
- 本地受控 SSE：入口、图解两种形式、旧报告、异常、章节与依据切换、390px 中英文与减少动效。
- Grok：只读源码审查，明确实际返回结论及处理结果。
- 发布：Cloudflare、真实 DeepSeek 输出、线上资产、GitHub CI 分别留证。
