# Agent 渐进引导与澄清设计

日期：2026-09-29。范围：首次提问、对话中的澄清、结果后的继续探索；保留直接输入及全部原有工具。

## 研究与判断

| 一手依据                                                                                                                               | 可核实的设计原则                                                                           | 问卜的应用判断                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| [Google：Questions](https://developers.google.com/assistant/conversation-design/questions)                                             | 宽泛问题给用户自由，但不熟悉领域的用户难以开始；聚焦问题能降低理解成本，一次只问一个重点。 | 第一屏从生活意图开始，不要求先懂八字、塔罗或紫微。               |
| [Google：Chips](https://developers.google.com/assistant/conversation-design/chips)                                                     | 选项可澄清意图、发现下一步；标签应简短、相关，不能替用户臆造意图。                         | 用简短选项，所有内容先进入可编辑草稿；不把示例背景当作用户事实。 |
| [Microsoft：Disambiguate customer intent](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/cux-disambiguate-intent) | 早期提供选项能减少追问；应提供不匹配的出口，过多问题会像盘问。                             | 三个轻步骤，允许“不确定”、返回和直接输入；资料足够后立即处理。   |
| [GOV.UK：Question pages](https://design-system.service.gov.uk/patterns/question-pages/)                                                | 只问真正需要的信息，标明选填，允许合理的“不知道”，避免重复索取。                           | 背景选填；出生资料只在用户选择排盘且资料不足时再补充。           |

上述是公开设计指导，不是问卜的转化率实验。Google 页面属于已停止的 Assistant 产品文档，只采用其通用交互原则，不沿用平台的固定数量与字符限制。

## 方案选择

1. 只增加示例 prompt：实现轻，但仍由用户理解术语并改写大段话，不能解决问题。
2. 强制完整问卷：表达结构化，但增加进入成本，对已有明确问题的用户多余。
3. **采用内嵌、可跳过的渐进引导**：关心的事 → 想得到什么 → 选填背景与预览。直接对话始终可用。

## 界面与行为

- 首屏提供工作与选择、关系与沟通、认识自己、学习与求证，以及还没想好的出口。选项使用统一线性图标、纸张底色和清晰的短说明。
- 第二步根据意图提供三个具体目标和一个“先帮我问清楚”。后退修改意图时清除不兼容目标。
- 第三步可补充自己的情况；示例只作 placeholder。高级的探索方式选择默认收起；生活问题默认先聊，研习默认查阅资料。明确选择塔罗或易经并发送后才授权抽取；选择引导卡片本身不调用模型。
- 整理后的问题可预览，并通过“放入输入框”交给用户编辑和发送。已有草稿保留，重复选择仅替换上次添加的建议部分。每个会话独立引导状态。
- 对话中的 ask_user 显示可选回答、自己补充、不确定；选项先放入草稿，可追加细节。仅最新且成功等待的澄清可用，避免点击过时问题。
- 完成后显示与现有结果相关的少量追问入口。保留原牌阵和命盘，不自动重新抽取。报告内问题也先放入草稿。
- 引导状态变化使用短淡入和位移；尊重已有减少动效设置。键盘可操作，步骤切换聚焦题目，移动端不横向溢出。

## 模型与数据

- DeepSeek 继续处理全部实际对话与工具任务。引导只是用户可检查的输入辅助，不伪造模型响应或计算结果。
- 系统提示强化一次聚焦澄清、2–4 个简短互斥选项、允许不确定、不重复已提供信息；不把“认识自己”当作排盘或抽牌授权。
- 记录 guide_opened、guide_step、guide_draft_created、suggestion_selected 和 agent_started 的有限分类。只记录步骤编号、入口种类和现有模式，不记录生活意图、选择文字、背景、出生资料或对话。
- 观测指标：开始引导 → 第 2/3 步 → 生成草稿 → 实际发送；澄清选项使用与下一回合完成。事件统计仅是行为观测，不能直接宣称提升准确率或转化率。

## 验收

中文/英文；直接提问可用；修改与后退不丢自由输入；切换会话不串草稿；选项不自动发请求；完整引导生成正确请求；缺出生时间保持未知；澄清与追问复用已有结果；键盘焦点、390/320 px、减少动效；事件白名单拒收私密字段；本地测试、Grok review、部署和生产验证分开记录。
