# 问卜 Agent：生成过程的动效研究

日期：2026-09-28。范围：独立 Agent 入口内的提问、工具执行、流式回应、结果呈现与中断。目标是让真实处理过程更有节奏、结果更值得留存。

## 可核实依据

| 来源 | 资料要点 | 对问卜的设计判断 |
| --- | --- | --- |
| [IBM Carbon · Motion](https://carbondesignsystem.com/elements/motion/overview/) | 区分轻量任务反馈与重要时刻的表达性动效，使用不同节奏；提供静态替代 | 小步骤轻响应；提交和结果到达才使用明显的落印与展开 |
| [IBM Carbon · Choreography](https://carbondesignsystem.com/elements/motion/choreography/) | 将多个相关元素组织成连贯的运动关系 | 结果先到达，朱印和内部结构跟随，避免各处同时抢注意力 |
| [W3C · Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) | 支持关闭非必要交互动效及系统减少动效偏好 | 提供独立动效开关；关闭动画不停止模型、不隐藏状态 |
| [W3C · Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide) | 持续动态内容需要用户控制，不能妨碍阅读 | 等待中的循环可统一停下；已完成和异常状态不再循环 |
| [web.dev · High-performance CSS animations](https://web.dev/articles/animations-guide) | 优先 transform 与 opacity，谨慎对待引发布局和重绘的动画 | 不引入 Canvas、视频、持续粒子或动画库；不对正文做逐字回放 |

这些来源支持运动层级、可控性和实现约束；“纸墨成章”的视觉方向是针对当前品牌的设计判断。没有证据证明该动效会提高占卜准确性、模型能力、流量或转化。

## 三个方向及取舍

1. **纸墨成章（采用）**：纸页、朱印、细环与笔迹，延续现有纸色和墨绿。仪式集中在问题落纸、结构成形和报告入册。
2. **器物演示**：完整洗牌、掷币和转盘更具参与感，但容易把模型等待误解成真实抽取，还会拉长过程。仅在工具确实执行时用简化器物图形；结果严格取自实际数据。
3. **光效粒子**：能制造视觉强度，但与现有页面材质不一致、持续抢占注意力。没有采用。

## 事件与表达

| 收到的真实状态 | 表达 | 规则 |
| --- | --- | --- |
| 用户提交 | 问已落纸：问题轻移、朱印落定 | 一次 300–600ms；旧会话不重播 |
| 查阅工具开始 | 循迹参照：纸页微动、细环缓行 | 已读数量只取实际 source 事件 |
| 排盘工具开始 | 依序推演：八字四柱、紫微十二宫 | 不填入虚构天干地支或百分比 |
| 起卦／塔罗工具开始 | 此刻成象：简化币与牌形 | 不改变原始随机结果，不声称重新抽取 |
| write_report 开始 | 落笔成章：纸笔轻动 | 不先显示空的最终报告 |
| artifact 到达 | 正文立即出现，朱印与结构跟随 | 章节／四柱／卦爻轻微错峰；卦爻从下向上；总计不超过 900ms |
| 流式文字到达 | 小墨色游标 | 直接渲染真实片段，不人为放慢 |
| done 完成 | 收势为静态记录 | “本回合结束”不表示每一次工具尝试都成功 |
| 追问准备中 | 整理需要补充的信息 | 只表示工具正在处理；未收到问题时不要求用户回答 |
| 已收到追问／停止／错误／限额 | 待补充或暂歇 | 停止所有循环；保留既有结果；不显示成功庆祝 |

活动图形为装饰性 SVG，屏幕阅读器只收到明确的阶段文本。系统减少动效与页面开关都保留完整功能。事件 reducer、API、模型、引用守卫与四项原有工具不变。

## 验收方式

先用 `scripts/motion-preview.mjs` 播放明确标注的本地受控 SSE，覆盖慢响应、成功、失败、追问、停止、结果版本切换和移动布局；受控回放不等于真实模型验证。随后在生产站点完成一次真实 DeepSeek 对话。检查连续变化及终态，截图仅证明所捕获时刻。审查与发布证据另记于 reviews 目录。
