# 问卜原创塔罗插画

2026-09-29。使用内置 image generation 模型逐张预生成 78 张牌面与 1 张牌背，再压缩为网站静态 WebP。抽牌、对话、手记和图鉴共用同一份稳定 ID 映射；用户使用时不再生成图像，不增加抽牌等待或模型费用。

## 交付

- `public/images/tarot/`：79 张 600 × 900 的正式图片和 78 张 260 × 390 缩略图，均随 Git 发布。
- [逐张提示词](tarot-prompts.json)：共同的版画风格与每张牌的独立意象。
- [修订提示词](tarot-revisions.json)：倒吊人温和演绎、牌背、圣杯九 / 星币八 / 星币十的数量修正。
- [资源清单](tarot-assets.json)：图片路径、SHA-256、尺寸、大小。
- `src/data/tarot-art.ts`：牌 ID 与资源路径映射。
- `docs/art/originals/`：本机保存的生成原图，已忽略，不作为线上依赖。

画面是原创 AI 对传统意象的重新演绎，不是历史牌面的复制或考据复原。文字标签和正逆位由真实抽牌数据渲染，未交给图像模型绘字。逆位旋转同一张图，不改变抽中牌。倒吊人采用沉思者与倒影表现暂停、新视角；网站已说明部分意象采用温和表达。

## 质量控制

逐套联系表检查风格、牌号映射、画面完整性；对数字牌进一步检查杯、剑、杖、星币的数量。发现并重生成三张数量错误的图，修订后才发布。不要把整套生成完成当成视觉检查完成。

运行 `npm run audit:art` 检查 78 张唯一牌面、牌背、所有缩略图、尺寸、每张不超过 250 KB 及提示词记录，并更新确定性的资源清单。该检查已接入 `npm run verify` 和 GitHub CI。

画廊首先加载缩略图；放大层只在打开时请求正式图片。图片延迟加载，尺寸预留，原图关闭后卸载。生产缓存 1 天；这些路径没有内容哈希，不能使用永久 immutable 缓存。
